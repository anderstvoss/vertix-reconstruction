# Read me first — hardening blueprint setup

This is a snapshot of a maximally-hardened public Rust library repo,
templated for reuse. Before doing anything else (commits, pushes,
publish), follow the steps below to customise it for your project.

The blueprint is **opinionated**: AGPL-3.0 license, Rust 2024 edition,
SHA-pinned actions, harden-runner egress block on every Linux CI job,
OpenSSF Scorecard with publish, CodeQL with security-extended,
weekly + per-change gitleaks all-refs, CycloneDX SBOM on every push,
branch protection with 13 required-status contexts.

**Intended flow:** duplicate this repo as a **private** repo, customise
it (Steps 1-4), run the deep secret scan, flip it public, then apply and
verify the server-side controls (Step 5). Every CI job is gated on the
repo being public, so nothing runs (or costs anything) while private;
the flip is what activates and validates the hardening.

## Step 1 — Search-and-replace the template markers

The repo contains intentionally fake placeholders that you must
replace. From the repo root:

```bash
# What needs to change
grep -rln 'TEMPLATE_' .

# Replacements:
#   TEMPLATE_OWNER          → your GitHub username or org
#   TEMPLATE_REPO           → the new repo's name on GitHub
#   TEMPLATE_PROJECT_NAME   → human-readable project name (README, CONTRIBUTING titles)
#   TEMPLATE_CRATE_NAME     → the Rust crate name (snake_case, matches Cargo.toml + lib.rs)
#   TEMPLATE_MAINTAINER_EMAIL → email for SECURITY.md vulnerability reporting
#   TEMPLATE_VALID_CATEGORY → one of https://crates.io/category_slugs (e.g., "emulators", "hardware-support")
```

Sample one-shot sed (review the diff before committing):

```bash
sed -i \
  -e 's/TEMPLATE_OWNER/your-gh-handle/g' \
  -e 's/TEMPLATE_REPO/my-new-repo/g' \
  -e 's/TEMPLATE_PROJECT_NAME/My New Project/g' \
  -e 's/TEMPLATE_CRATE_NAME/my_new_project/g' \
  -e 's/TEMPLATE_MAINTAINER_EMAIL/you@example.com/g' \
  -e 's/TEMPLATE_VALID_CATEGORY/emulators/g' \
  $(grep -rln 'TEMPLATE_' .)
```

Also update by hand:
- `Cargo.toml`: `description`, `keywords` (max 5, all lowercase, hyphens OK).
- `README.md`: rewrite the project description, status line, intended audience.
- `CHANGELOG.md`: empty.
- `src/lib.rs`: rewrite the docstring.

Verify nothing left:

```bash
grep -rln 'TEMPLATE_' .
```

## Step 2 — Pick your license

The blueprint ships AGPL-3.0-only by default. If you want something
else (MIT, Apache-2.0, etc.):

1. Replace `LICENSE` with the chosen license's text. Common sources:
   - <https://choosealicense.com/>
   - <https://spdx.org/licenses/>
2. Update `Cargo.toml`'s `[package].license` to the matching SPDX
   identifier.
3. Update `deny.toml`'s `[licenses].allow` if your new license isn't
   already in the list. AGPL-3.0-only is included; if you switch to
   MIT or Apache-2.0, those are also in the default allow set, so no
   change needed.
4. Update the License section in `README.md`, `CONTRIBUTING.md`, and
   `SECURITY.md` text.

## Step 3 — Adapt for crate type (library vs binary vs both)

The blueprint defaults to a **library** crate (`src/lib.rs` with a
`#[cfg(test)] mod tests` smoke test, no `[[bin]]`).

### Library only (default)
No change needed.

### Binary only
1. Rename `src/lib.rs` to `src/main.rs`.
2. Replace its contents with:
   ```rust
   fn main() {
       println!("Hello, world!");
   }
   ```
3. In `Cargo.toml`, **remove** `[lints.rust].missing_docs = "warn"` if
   you'd added it — `missing_docs` fires unhelpfully on bins.

### Both (library + binary that exposes a CLI over the library)
Keep `src/lib.rs` as the library root, add `src/main.rs` for the
binary, and let Cargo auto-detect both. No `Cargo.toml` change
required for the default layout.

## Step 4 — Adapt for a different language

Some pieces of the blueprint are language-agnostic; others are
Rust-specific. Adaptation map:

### Keep as-is regardless of language

- `.githooks/{pre-commit,pre-push}` — generic wrappers around the
  `pre-commit` Python package.
- `.pre-commit-config.yaml`'s **first half** — gitleaks, file-format
  hooks (yaml/toml/json/EOL/trailing whitespace/etc.), all the local
  pygrep blockers (env files, private keys, local paths, cloud URIs,
  IPs).
- `.github/workflows/{gitleaks-history,scorecard,codeql,sbom}.yml` —
  language-agnostic *concepts*; needs language-specific tweaks
  inside.
- `scripts/deep-scan.sh` — gitleaks only, language-agnostic.
- `SECURITY.md`, `CONTRIBUTING.md`, `LICENSE`, issue templates,
  `dependabot.yml`'s structure — all generic.
- `docs/REPO-SETUP.md`, `docs/HARDENING-CHECKLIST.md` — read for the
  philosophy; expect to rewrite the language-specific sections.

### Tooling status: proven vs. not yet proven

"Proven" means the exact configuration has run green in public CI on a
real repository with this blueprint. Prefer proven pieces; when you use
an unproven row, you are the validation, so feed the working config back
into this template once it is green.

| Piece | Status | Where it is proven / what to use |
|---|---|---|
| Rust: rustfmt, clippy `-D warnings` (all + pedantic), `--locked` builds, MSRV job, 3-OS test matrix | **Proven** | this template; `anderstvoss/virtualgamepad` |
| Rust: `unsafe_code = "forbid"`; FFI crates opt out with `#![allow(unsafe_code)]` and `clippy::undocumented_unsafe_blocks = "deny"` | **Proven** | `anderstvoss/virtualgamepad` (16-crate workspace with FFI broker) |
| Rust supply chain: cargo-deny (`deny.toml`), cargo-audit 0.22.2 `--locked`, cargo-cyclonedx 0.5.9 | **Proven** | this template; `anderstvoss/virtualgamepad` |
| Python helpers: `ruff-check` hook (`ruff.toml`: `F` + `S`), stdlib `unittest` under `scripts/tests`, `python-scripts` CI job | **Proven** | `anderstvoss/virtualgamepad` (~35 host/lab scripts) |
| Hash-locked pip install (`uv pip compile --generate-hashes`, `--require-hashes --no-deps`) | **Proven** | this template (pre-commit install in `policy`) |
| CodeQL `actions` language (workflow scanning) | **Proven** | this template; `anderstvoss/virtualgamepad` |
| Python as the main language: `pyproject.toml` + `uv.lock` (`uv sync --locked`), `ruff format`, `mypy --strict`/pyright, `pytest`, `pip-audit`, `cyclonedx-py`, CodeQL `python` | Not yet proven | follow the table below |
| TypeScript / Node: lockfile + `npm ci` with `ignore-scripts=true`, `tsc --noEmit` strict, `eslint --max-warnings 0`, `prettier --check`, `npm audit`/`osv-scanner`, `@cyclonedx/cyclonedx-npm`, CodeQL `javascript-typescript` | Not yet proven | follow the table below |
| Go: `go.mod` `toolchain`, `-mod=readonly`, `gofmt`, `go vet` + `staticcheck` + `gosec`, `go test -race`, `govulncheck`, `cyclonedx-gomod`, CodeQL `go` | Not yet proven | follow the table below |
| C / C++: `-Wall -Wextra -Werror`, hardening flags, ASan/UBSan job, `clang-tidy`, CodeQL `c-cpp` | Not yet proven | follow the table below |

### Replace Rust-specific pieces

| Rust piece | Python | Go | Node/TS |
|---|---|---|---|
| `Cargo.toml` | `pyproject.toml` | `go.mod` | `package.json` |
| `Cargo.lock` + `--locked` | `uv.lock` + `uv sync --locked` | `go.sum` + `-mod=readonly` | lockfile + `npm ci` / `pnpm install --frozen-lockfile` |
| `rust-toolchain.toml` | `.python-version` + `requires-python` | `toolchain` directive | `.nvmrc` + `engines` + `packageManager` |
| `deny.toml` (licenses, sources) | `pip-licenses` allowlist; index pinned to PyPI | `go-licenses check` | `license-checker` allowlist; registry pinned in `.npmrc` |
| `cargo fmt` | `ruff format --check` | `gofmt -l` (must be empty) | `prettier --check` |
| `cargo clippy -D warnings` | `ruff check` (keep `F` + `S`, add `B`, `UP`) + `mypy --strict` | `go vet` + `staticcheck` + `gosec` | `eslint --max-warnings 0` + `tsc --noEmit` |
| `unsafe_code = "forbid"` | ruff `S` bans `eval`/`exec`/`pickle`/`shell=True` | ban `unsafe`/cgo outside one package | ban `eval`, `new Function`, string `exec` |
| `cargo test` | `pytest` | `go test -race ./...` | `vitest` / `jest` |
| `cargo-audit` | `pip-audit` | `govulncheck` | `npm audit --audit-level=moderate` / `osv-scanner` |
| `cargo-cyclonedx` | `cyclonedx-py` | `cyclonedx-gomod` | `@cyclonedx/cyclonedx-npm` |
| `dtolnay/rust-toolchain` | `actions/setup-python` | `actions/setup-go` | `actions/setup-node` |
| harden-runner Rust endpoints (`static.rust-lang.org`, `*.crates.io`) | `pypi.org`, `files.pythonhosted.org` | `proxy.golang.org`, `sum.golang.org`, `storage.googleapis.com` | `registry.npmjs.org` |
| Dependabot `cargo` | `pip` / `uv` | `gomod` | `npm` |

Pin every tool you install in CI to an exact version (and `--locked` or
hash-pinned where the installer supports it), and pin every new action to
a full commit SHA.

### Concrete workflow swaps

In `.github/workflows/ci.yml`:
- Replace every `Install Rust` step with the language's setup action.
- Replace `cargo fmt` / `clippy` / `check` / `test` / `cargo-deny` /
  `cargo-audit` with the equivalents from the table above.
- Drop the `msrv` job or repurpose it (e.g., Python's "test on
  oldest supported version").
- Keep `policy` (it runs pre-commit) and `harden-runner` blocks.
- Adjust the `dependency-review` action's `fail-on-severity` if the
  language ecosystem has noisier advisories.

In `.github/workflows/sbom.yml`:
- Replace `cargo-cyclonedx` with the equivalent CycloneDX generator.

In `.github/workflows/codeql.yml`:
- Change the `rust` matrix entry to your language. Keep the `actions`
  entry: it scans the workflow files themselves. CodeQL supports
  `actions, c-cpp, csharp, go, java-kotlin, javascript-typescript,
  python, ruby, rust, swift`.
- Drop the `Build (manual)` step if the language is interpreted —
  CodeQL only needs explicit builds for compiled languages without
  a manifest-driven build (Rust, Go).

In `.pre-commit-config.yaml`:
- Drop the `cargo-fmt`, `cargo-check`, `cargo-clippy`, `cargo-test`,
  `cargo-deny`, `cargo-audit` local hooks.
- Add language-specific hooks (e.g., `ruff` for Python, `gofmt` for
  Go).

In `.github/requirements/pre-commit.txt`:
- Regenerate by editing `.in` if you change pre-commit version,
  then `uv pip compile pre-commit.in --generate-hashes --output-file pre-commit.txt`.

In `.gitignore`:
- Replace `/target`, `*.profraw`, `*.profdata`, `tarpaulin-report.html`
  with the language's build-artefact patterns.

In `Cargo.toml` `[lints]`:
- Drop the file; configure the language's linter in its own config
  (`ruff.toml`, `.golangci.yml`, `.eslintrc`, etc.).

## Step 5 — Apply the blueprint to GitHub

Follow [`docs/HARDENING-CHECKLIST.md`](docs/HARDENING-CHECKLIST.md)
end-to-end and [`GOING_PUBLIC.md`](GOING_PUBLIC.md) before the flip.
Highlights:

1. Duplicate this template as a **private** repo
   (`gh repo create <owner>/<repo> --private --template <owner>/baseline-hardened-repo`).
2. Local clone setup: `git config core.hooksPath .githooks`,
   `cargo install cargo-deny cargo-audit`, `pipx install pre-commit`.
3. Verify hooks: `pre-commit run --all-files` and
   `pre-commit run --all-files --hook-stage pre-push`.
4. **Before the flip:** `scripts/deep-scan.sh` must pass. Once public,
   every reachable commit is public.
5. Flip public, then immediately enable the server-side controls via
   `gh api` per [`docs/REPO-SETUP.md`](docs/REPO-SETUP.md) Step 3:
   secret scanning, push protection, PVR, Dependabot alerts +
   auto-updates, branch protection with the required-status contexts,
   read-only Actions token, fork-PR approval, `v*` tag ruleset.
6. Open a draft PR: every required check must go green.
7. Run the Step 5 verification and the push-protection sanity test in
   `docs/REPO-SETUP.md`; confirm Scorecard SARIF appears in the
   Security tab.

The required-status contexts in `docs/REPO-SETUP.md`'s branch-
protection payload match this snapshot's workflow job names exactly.
If you rename, add, or remove a job, **update both** the workflow
and the contexts array in lock-step.
